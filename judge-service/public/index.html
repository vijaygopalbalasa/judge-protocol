Judge Protocol API

Ask a neutral, deterministic judge to rule on an ERC-8183 job. The ruling is a pure function of the acceptance criteria written into the job and the deliverable the provider committed to on chain, so it does not matter who asks, and anyone can recompute it.

Use it in four steps

  1. Create the job on Circle's ERC-8183 contract (0x0747EEf0706327138c69792bF28Cd525089e4583) with the evaluator set to JudgeEvaluator 0x6EFF7d4BB514d341AbEd90bF4c667d0A980173AD.
  2. Put the acceptance criteria in the job description as a fenced judge-criteria JSON block (checks: length, contains, schema, checksum, http-endpoint).
  3. The provider submits with optParams set to deliverableURI: data:…, or an https URI (at most 1 MB, no redirects) or an ipfs URI (best effort).
  4. Ask for the ruling: POST /api/judge with the job id and the submit transaction hash. The judge settles the escrow on chain: pass releases it to the provider, fail refunds the client.
curl -X POST https://judge-protocol-api.vercel.app/api/judge \
  -H 'content-type: application/json' \
  -d '{"jobId":"186740","submitTx":"0x…"}'

Endpoints

POST /api/judgeRule now on a Submitted job that names this judge. Body: jobId, optional submitTx (needed for submissions older than about 4 hours).
GET /api/judge?jobId=NRead-only status: pending, judged (with the on-chain verdict), not-submitted, expired, closed, not-ours, or not-found.
POST /api/evaluateDry run: the exact checks, score and evidenceHash the judge would produce for a deliverable. Never signs, never settles, never makes a network request. For your own escrow, or to self-check before submitting.
POST /api/x402/judgeThe same ruling, paid over x402: 0.01 USDC through Circle Gateway on Arc testnet, settled only once the judge has a verdict ready and before it signs, so one payment never buys two rulings. Answers 402 with the terms for a job it can rule; everything else is free.
GET /api/erc8412?jobId=NERC-8412: the job's criteria document and the preregister arguments for its client, and once the judge has attested, the whole record rebuilt from chain data with our checker's result. See docs/ERC-8412.md.
GET /api/healthThe judge, its signer and whether it is authorized on chain, whether the relayer has gas, and the ERC-8412 registry and attestor.

Honest limits

  • Arc testnet only. Best effort, no uptime guarantee: rulings happen on request, and a daily sweep catches jobs from the last two days that nobody asked about. If the judge never rules, claimRefund after expiredAt returns the client's funds.
  • Jobs with a budget under 0.01 USDC are skipped (spam guard).
  • Deterministic checks cover objective, structured deliverables. An http-endpoint check is a live network probe recorded once at judging time; it cannot be re-run later as the judge saw it.
